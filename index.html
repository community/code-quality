Week 1

Configure Your Foundation

Get GitHub Code Quality switched on so findings start flowing from day one

0 / 3
  • Before any team can turn it on, an enterprise owner needs to allow GitHub Code Quality. This one setting unlocks the product for every organization underneath it.
    Unlock the product
    💡 Tip: GitHub Actions must also be enabled, because Code Quality runs each CodeQL analysis as an action. Confirm that first to avoid a failed rollout.
  • Enable Code Quality for a single repository or for every repo in your org all at once. Findings appear inline on pull requests and across your default branch immediately.
    Get started
    💡 Tip: Rule-based CodeQL analysis covers C#, Go, Java, JavaScript, Python, Ruby, and TypeScript. AI-powered analysis also runs on recently changed code, including languages beyond that list.
  • Skip hand-authoring CI config. An AI-powered agent can analyze your repo, identify your test framework, run your tests with coverage enabled, and open a pull request with a working coverage workflow.
    Automate setup
    💡 Tip: The agent opens its pull request with a planning commit first, so if it shows 0 changed files, wait a few minutes and refresh. If it stops early, review its session log in your repository’s Tasks tab. See how the agent works.
Steps completed? Here's the exec recap: GitHub Code Quality is configured and scanning, with a coverage baseline in place and ready to roll out.
Week 2

Customize Your Standards

Tune thresholds and scope so quality gates match how your teams actually build

0 / 3
  • Use rulesets to block pull requests that don’t meet your standards, so new quality debt stops accumulating in your codebase.
    Set your bar
    💡 Tip: Start permissive in a pilot repo and tighten as your teams adapt. Blocking too aggressively on day one is the fastest way to lose developer goodwill.
  • Prevent pull requests from merging when uploaded coverage falls below the level your team requires, protecting the test coverage you’ve already earned.
    Protect coverage
    💡 Tip: Developers can see which files are dragging coverage down in the coverage summary posted on each pull request.
  • Control Code Quality from a single point with the org-level Repository access setting, and decide exactly which repos are in scope.
    Take control
    💡 Tip: You can target every repo, a specific list, or a dynamic filter that automatically picks up new repos as they're created.
Steps completed? Here's the exec recap: Quality and coverage thresholds now reflect your org’s engineering standards, with guardrails on which repos are held to them.
Week 3

Build Adoption

Expand coverage and turn findings into merged fixes

0 / 4
  • Bring Code Quality to every team with confidence: pilot with a small group first, tune your thresholds, then expand across the organization.
    Expand coverage
    💡 Tip: Pick pilot repos with engaged maintainers and active PR traffic. Their feedback is what makes the wider rollout land.
  • Adoption happens in the pull request. Walk your teams through applying a one-click Copilot autofix, delegating the work to Copilot, or dismissing findings that aren’t relevant.
    Enable your devs
    💡 Tip: Pair this with guidance on resolving a threshold block, so a blocked pull request never becomes a support ticket.
  • Help your teams build knowledge to expand Code Quality across your org with this self-paced learning pathway.
    Empower your team
    💡 Tip: Share the pathway with teams as you expand Code Quality to new repos, so they can build on what’s already working.
  • Generate fixes for backlog items by assigning them to Copilot via agentic autofix.
    Clear the debt
    💡 Tip: Be sure to also review findings in recently merged files: AI-powered analysis catches issues that rule-based queries were never written for.
Steps completed? Here's the exec recap: GitHub Code Quality is live across teams, developers know how to act on findings in the pull request, and existing quality debt is actively being paid down.
Week 4

Prove Value

Measure code health, show the impact, and grow with confidence

0 / 3
  • Use your maintainability and reliability scores to understand where your codebase actually stands, so teams focus remediation where it matters most.
    Read your score
    💡 Tip: Want a worked example? Follow the tutorial on raising your repository’s code quality score.
  • Use the org-level Code Quality dashboard to spot repos that need attention, and track how open findings trend over time.
    View insights
    💡 Tip: Code Quality reports are available in Security Overview alongside your other security tools, so one view covers both posture and code health for audits and compliance reporting.
  • See exactly where charges come from — active committers, AI credits, and Actions minutes — and use the levers that keep spend predictable as you scale.
    Prove the ROI
    💡 Tip: For the full cost model, including how per-seat licensing and AI credits are calculated, see GitHub Code Quality billing.
